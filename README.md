# Minecraft 統合版(BuildHelper)

少人数のサバイバルワールドで、**協力建築とテレポート移動を楽にする**ための Minecraft 統合版
(Bedrock Edition)向けアドオン。コマンドを覚えなくても、アイテムの右クリックとフォーム UI だけで使える。

> Minecraft の非公式アドオンです。Mojang Studios / Microsoft とは関係ありません。

## 主な機能

- **設計図の保存** … 範囲を選んでワールド内のストラクチャとして保存(最大 64×64×64)
- **ゴースト表示** … まだ置いていないブロックの位置を粒で表示
- **進捗チェック** … 設置済み / 総数 / 完成率
- **持ち寄りリスト** … 足りない資材を、選んだメンバーで均等に割り振る
- **ミラー設置** … 手で置いたブロックを対称の位置にも置く(資材は実際に消費する)
- **ガイドライン** … 直線・グリッドの目印を一時的に表示
- **集合テレポート** … ログイン中の他のプレイヤー全員を自分の場所へ呼ぶ
- **ガイドブック** … 使い方・レシピ・パッチノートを読めるアイテム(初めて入ったときに 1 冊配られる)

UI の表記はすべて日本語(英語の言語ファイルにも日本語を入れてある)。

## 開発状況

**Minecraft の実機での動作確認はまだ済んでいません。** スクリプトの主な動作は、
`@minecraft/server` / `@minecraft/server-ui` の最小スタブの上で実際のスクリプトを動かすテストで
確かめていますが、パーティクルの見え方・フォームの実際の表示・API の細かい挙動は確かめられていません。
実機で確かめる項目は下の「[実機での確認項目](#実機での確認項目)」にまとめてあります。

## 動作環境

| 項目 | 値 |
|---|---|
| Minecraft 統合版 | 1.21.90 以降(`min_engine_version` 1.21.90) |
| Script API | `@minecraft/server` 2.0.0 / `@minecraft/server-ui` 2.0.0(安定版のみ。ベータ API は使わない) |

## 入れ方

### .mcaddon を作って取り込む

Python 3 と Pillow が要る(ビルドの前にテクスチャの形も検査するため)。

```
pip install pillow
python tools/build_mcaddon.py     # -> dist/build_support_addon.mcaddon
```

1. できた `.mcaddon` をダブルクリック(または Minecraft の「インポート」)で取り込む。
2. ワールド設定で **ビヘイビアパック** を適用する。依存関係が書いてあるので、リソースパックは自動で適用される。
3. ワールドに入ると **建築支援ガイドブック** が 1 冊配られる。右クリックで開き、「はじめに」から読む。
4. 設計図ツールと集合ビーコンは **作業台でクラフト** できる(レシピは下記)。チートが ON のワールドなら `/give` でも手に入る。

```
/give @s buildhelper:blueprint_wand
/give @s buildhelper:rally_beacon
/give @s buildhelper:guide_book
```

### フォルダをそのまま置く

`BuildHelperBP` を `com.mojang/behavior_packs`(または `development_behavior_packs`)へ、
`BuildHelperRP` を `com.mojang/resource_packs`(または `development_resource_packs`)へコピーする。

Windows のランチャー版なら `tools/deploy.ps1` が
`%APPDATA%\Minecraft Bedrock\Users\Shared\games\com.mojang` の `behavior_packs` / `resource_packs` へ
ミラーコピーする。Minecraft を完全に終了してから、**PowerShell 7(`pwsh`)で**実行する
(スクリプトは BOM なしの UTF-8 なので、Windows PowerShell 5.1 では日本語の部分が読めず構文エラーになる)。

```
pwsh -ExecutionPolicy Bypass -File tools/deploy.ps1
```

### アンインストール

ワールド設定からパックを外すだけ。保存した設計図のデータはワールド側に残るので、
もう一度適用すれば一覧はそのまま戻る。

## アイテム一覧

| 識別子 | 表示名 | 役割 |
|--------|--------|------|
| `buildhelper:blueprint_wand` | 設計図ツール | 範囲選択とメインメニューの入口 |
| `buildhelper:rally_beacon` | 集合ビーコン | 使うだけで集合テレポートを実行 |
| `buildhelper:guide_book` | 建築支援ガイドブック | チュートリアル・レシピ・パッチノートを読む |

### ガイドブック

**初めてワールドに入ったプレイヤーへ自動で 1 冊配られる**(1 人につき 1 回だけ。
インベントリが満杯なら足元に落とす)。手に持って右クリックで開く。

収録内容は「はじめに」「設計図をつくる」「ゴースト表示と進捗」「持ち寄りリスト」
「ミラー設置」「ガイドライン」「集合テレポート」「クラフトレシピ」「パッチノート」「制作者」。

> 統合版の安定版 API には、スクリプトからバニラの「書かれた本」にページを差し込む手段が無い。
> そのためガイドブックは **カスタムアイテム＋フォーム UI** で本を再現している。
> 本文を直したいときは `BuildHelperBP/scripts/book.js` だけを編集すればよい。

### クラフトレシピ

すべて **作業台** で作れる。バニラのレシピとは衝突しない。

| 完成品 | 種類 | 配置 / 材料 | 完成数 |
|--------|------|-------------|--------|
| 設計図ツール | 定形 | `["IPI","PLP","IPI"]` I=鉄インゴット, P=紙, L=ラピスラズリ | 1 |
| 集合ビーコン | 定形 | `[" G ","GEG","OOO"]` G=金インゴット, E=エンダーパール, O=黒曜石 | 1 |
| 建築支援ガイドブック | 不定形 | 本 ×1 + 紙 ×1 + ラピスラズリ ×1 | 1 |

### 設計図ツールの操作

| 操作 | 動作 |
|------|------|
| ブロックを **左クリック**(殴る) | その位置を **始点** に設定(ブロックは壊れない) |
| ブロックを **右クリック** | その位置を **終点** に設定 |
| **スニーク＋右クリック** / 空中で右クリック | **建築支援メニュー** を開く |

左クリックが使えない場面のために、メニューの「設計図管理」からも
「現在地を始点にする」「現在地を終点にする」で指定できる。

## 機能ごとの使い方

### 1. 設計図の保存

始点と終点を指定 → メニュー →「設計図管理」→「この範囲を設計図として保存」→ 名前を入力。

- 保存先は `StructureManager`(ワールド内のストラクチャ領域)。
- **1 辺が 64 ブロックを超える範囲は保存できない。**「範囲が大きすぎます(最大 64x64x64)」と出る。
- 同じ名前で保存しようとすると上書きの確認が出る。「はい」を選んだときだけ既存のデータを消して保存し直す。
- 始点と終点が別のディメンションにあるときは保存できない。

### 2. ゴースト表示

「設計図管理」→「保存済みの設計図一覧」→ 設計図を選ぶ →「ゴースト表示をONにする」→ 基準座標を入力。

- 基準座標は **設計図の最小角(西・下・北の隅)が来る位置**。既定値は現在地。
- **まだ置かれていないブロック** が緑の粒(`villager_happy`)で表示される。
- 描き直しは **10 tick(0.5 秒)おき**。1 回で判定するブロック数と粒の数に上限があるので、
  大きな設計図でも毎 tick の全走査は起きない。
- 表示は自分の周囲 20 ブロックまで。チャンクが読み込まれていない範囲はその回を飛ばし、次の回に持ち越す。
- ON/OFF はプレイヤーごとに保存され、**ワールドを閉じて開き直しても残る**。

### 3. 進捗チェック

ゴースト表示中の設計図を開いて「進捗を確認」。

設置済みブロック数 / 総ブロック数 / 完成率(%)が出る。
判定は設計図側の `BlockPermutation` とワールドの実ブロックを 1 件ずつ比べており、
**種類が同じでも向きや上下が違えば未設置扱い**。

読み込まれていないチャンクのブロックは分母からも分子からも除き、
「未読み込みチャンクなどの N ブロックは判定から除外しました」と書き添える。

### 4. 持ち寄りリスト

ゴースト表示中の設計図を開いて「持ち寄りリストを作成」→ 参加メンバーをトグルで選ぶ。

ブロックの種類ごとに次の 3 つが出る。

- **必要**: まだ置かれていない数
- **所持**: 選んだメンバー全員のインベントリ内の合計
- **不足**: 必要 − 所持(マイナスにはならない)

不足分を人数で均等に割り、**割り切れない端数は一覧の先頭のプレイヤー** に寄せる。
自分 1 人だけを選んだ場合は割らずに、不足数をそのまま出す。

### 5. ミラー設置

メニュー →「ミラー設定」→ 有効にする＋基準面(X/Y/Z 軸)と基準座標を入力。

- 以後、**手でブロックを置くたびに** 基準面に対して対称の位置にも同じブロックが置かれる。
- **資材はインベントリから実際に消費する**(通常の設置 1 個 + ミラー分 1 個 = 合計 2 個)。
  fill/clone コマンドや `StructureManager.place` によるタダの生成はしない。
- **サバイバル専用**。クリエイティブでは消費が起きないので、ミラー設置も動かない。
- ミラー分の在庫が足りないときは、**対称側の設置だけを飛ばす**(手で置いた分は普通に置かれる)。
  この警告は **1 回だけ** 出る。
- 対称先が空気でない場合は上書きせずに飛ばす。
- 階段やハーフブロックなど向きを持つブロックは、反転軸に合わせて向きも反転させる。
- 消費するアイテムは、まず **その瞬間に手に持っている物**、無ければ置かれたブロックの識別子で探す。
  レッドストーンダストや作物のように **ブロックとアイテムの識別子が違うもの** は、
  手持ちが切れているとミラー分を消費できずに飛ばされる。

### 6. ガイドライン表示

メニュー →「ガイドライン表示」→ 種類(直線／グリッド)・方向・基準点・間隔(1〜16)・表示時間(10〜300 秒)。

- 直線は指定した軸に沿って伸び、**間隔ごとに目印の粒** が入る。
- グリッドは指定した軸に垂直な平面へ格子点を打つ。
- 指定した秒数で自動で消え、チャットに終了のメッセージが出る。

### 7. 集合テレポート

**集合ビーコンを右クリック**、またはメニュー →「集合テレポート」。

- 同じワールドにログイン中の **他のプレイヤー全員** が、実行した人の現在地へ移動する。
- 自分以外が誰もいない場合はテレポートせず「他に参加者がいません。」と出る。
- **プレイヤーごとに 60 秒のクールダウン** がある。クールダウン中は残り秒数を出して実行しない。
- 溶岩の上や窒息する座標かどうかの安全判定はせず、バニラの teleport 処理に任せている。

## 割り切り・やっていないこと

- **集合テレポートのコマンド版は無い。** カスタムコマンドを足す API(`StartupEvent.customCommandRegistry`)は
  `@minecraft/server` 2.1.0 / Minecraft 1.21.100 以降で安定版になったもので、このアドオンが前提にしている
  2.0.0 には無い。ベータ API を使わない方針を優先し、アイテムとメニューだけにしている。
- **ブロック名の日本語表示は辞書方式。** 統合版の言語キー(`tile.<id>.name`)はブロックによって
  命名規則が揺れ、翻訳できないものがある。建築でよく使うブロック約 130 種を
  `BuildHelperBP/scripts/block_names.js` の表で日本語にし、**表に無いブロックは識別子をそのまま表示** する。
- **進捗・持ち寄りリストは「ゴースト表示中の設計図」が対象。** 基準座標が決まらないと現地と照らし合わせられないため。
- 拠点保護・権限ランク・ログイン通知・共有ホーム・経済／ショップ・多言語対応などは入れていない。

## 実機での確認項目

まだ実機で 1 周していない。上から順に試す想定。

**導入**
- [ ] `.mcaddon` をインポートしてエラーなく取り込める
- [ ] BP を適用すると RP も自動で適用される
- [ ] コンテンツログ(設定 → クリエイター → コンテンツログ GUI)にエラー・警告が出ない
- [ ] `/give` で 3 アイテムが手に入り、日本語名と専用アイコン(欠けたテクスチャでない)が出る

**ガイドブック**
- [ ] 新しいワールドに初めて入ると、ガイドブックが自動で配られる
- [ ] 一度出て入り直しても 2 冊目は配られない
- [ ] 右クリックで目次が開き、各章・パッチノート・制作者が読める

**クラフト**
- [ ] サバイバルの作業台で 3 アイテムすべてがレシピどおり作れ、レシピブックにも出る
- [ ] 既存のバニラのレシピを壊していない(ビーコン・本などが普通に作れる)

**設計図の保存**
- [ ] 左クリックで始点、右クリックで終点が設定され、アクションバーに座標が出る
- [ ] 32x32x32 の範囲を保存 → 一覧に出る
- [ ] 70x70x70 の範囲で保存 → 「範囲が大きすぎます」と出て、保存されない
- [ ] 同じ名前で保存 → 上書きの確認が出て、「いいえ」なら元のデータが残る

**ゴースト表示**
- [ ] 保存した設計図を選んでゴースト表示 ON → 指定座標を起点に緑の粒が出る
- [ ] OFF にすると粒が消える
- [ ] 粒が出ている間、目立つカクつき(TPS の低下)が無い

**進捗チェック**
- [ ] 設計図の半分だけブロックを置く → 完成率がおよそ 50% と出る
- [ ] すべて置く → 100% になる

**持ち寄りリスト**
- [ ] 不足が石 10 個・木材 20 個、メンバー 2 人(所持 0)→ 各メンバーに石 5 個・木材 10 個と出る
- [ ] メンバーが石を持っている → 「所持」に反映され「不足」が減る
- [ ] 自分 1 人だけ選ぶ → 不足数がそのまま出る

**ミラー設置**
- [ ] サバイバルで基準面を設定し、丸石 2 個を持って 1 個置く → 対称の位置にも置かれ、丸石が 0 個になる
- [ ] 丸石 1 個だけ持って置く → 手前の 1 個だけ置かれ、警告が 1 回だけ出る
- [ ] 対称先が既にブロックで埋まっている → 上書きされない
- [ ] クリエイティブでは対称側の設置が起きない
- [ ] 階段を置くと、対称側の階段の向きが反転している

**ガイドライン**
- [ ] 間隔 5・表示時間 30 秒で直線を表示 → 粒が出て、30 秒後に自動で消える
- [ ] グリッドでも格子状に出る

**集合テレポート**
- [ ] 3 人オンラインで実行 → 残りの 2 人が実行者の座標へ移動する
- [ ] 1 人だけで実行 → 「他に参加者がいません。」と出て、何も起きない
- [ ] 続けて実行 → 残り秒数が出て、テレポートしない

**ワールドを開き直したとき**
- [ ] ワールドを閉じて開き直す → 設計図一覧・ゴースト表示の設定・ミラー設定が残っている

## 開発

```
pip install pillow
python tools/generate_textures.py   # テクスチャと pack_icon を作り直す(16x16 / RGBA を自動で検査)
python tools/build_mcaddon.py       # 検査してから dist/build_support_addon.mcaddon を出す
node tools/harness/test.mjs         # スクリプトの自動テスト(Minecraft を起動せずに Node で動かす)
```

`build_mcaddon.py` はまとめる前に次を検査し、1 つでも問題があれば止まる。

- すべての JSON の構文
- manifest の UUID がすべて異なること／BP の依存関係が RP を正しく指していること
- **ベータ API を使っていないこと**(manifest とスクリプト本文の両方)
- `item_texture.json` の全キーに対応する PNG があり、正方形・RGBA であること
- アイテム JSON の `minecraft:icon` が `item_texture.json` のキーと一致すること
- 全アイテムの表示名が `ja_JP.lang` にあり、`ja_JP.lang` と `en_US.lang` が同じであること
- スクリプトに `StructureManager.place` / fill / clone / `runCommand` が含まれないこと
  (ブロックをタダで生成しない、という方針の担保)

テクスチャと pack_icon は `tools/generate_textures.py` が「パレット＋16×16 の文字のグリッド」から
描いたもので、バニラの素材は使っていない。

### スクリプトの自動テスト

`tools/harness/node_modules/@minecraft/` に `@minecraft/server` / `@minecraft/server-ui` の
**最小スタブ** を自作して置いてある(本物の API ではない)。`npm install` は不要。
`test.mjs` は実行のたびに `BuildHelperBP/scripts/` の現物を `tools/harness/` へ写して読み込み、
次を確かめる(全 52 項目)。

- ガイドブックが初回ログインで 1 冊だけ配られること・リスポーンでは配られないこと・
  インベントリが満杯なら足元に落ちること・目次と各章が開けること
- 範囲選択 → 保存 → 一覧への反映(`createFromWorld` が呼ばれること)
- 70x70x70 でエラーになり、保存件数が増えないこと
- 8 ブロック中 4 ブロック設置で **完成率 50%** になること
- ゴースト表示の粒が未設置の座標にだけ出て、上限を超えないこと
- 持ち寄りリストの計算(必要 4 / 所持 1 / 不足 3 → Alice:2 / Bob:1 と端数が先頭に寄る)
- ミラー設置で **丸石が 2 個消費される** こと・在庫不足で **警告が 1 回だけ** 出ること・
  階段の向きが反転すること・クリエイティブでは動かないこと
- ガイドラインが表示され、指定秒数で消えること
- 集合テレポートの移動・クールダウンの残り秒数・1 人のときのメッセージ
- 実行中に `console.warn`(＝コンテンツログの警告)が 1 件も出ないこと

**あくまでスタブでの検証** なので、実機テストの代わりにはならない。

### 版を上げるとき

1. コードを直す → `BuildHelperBP/manifest.json` と `BuildHelperRP/manifest.json` の
   `version`(と BP の RP 依存の `version`)をすべて同じ番号に上げる。
   `BuildHelperBP/scripts/book.js` の `PATCH_NOTES` の先頭にも 1 つ足す
2. `python tools/build_mcaddon.py` — パック名の末尾に `v1.0.1` のように版が自動で入る
3. Minecraft を完全に終了 → `.mcaddon` をインポート → ワールド設定でいちばん大きい版を選ぶ

